# Viva Voce Preparation Guide: Animal Shelter Management System in Scala

This document contains 30 comprehensive, beginner-friendly viva questions and answers designed specifically for 2nd-year B.Tech CSE students preparing to defend this project.

---

### Q1. What is Scala?
**Answer:** Scala (Scalable Language) is a modern, statically-typed programming language that seamlessly integrates **Object-Oriented Programming (OOP)** and **Functional Programming (FP)**. It runs on the Java Virtual Machine (JVM) and provides full interoperability with Java libraries.

---

### Q2. Why did we choose Scala for this project?
**Answer:**
1. **Concise Syntax:** Less boilerplate compared to Java (no explicit getters/setters needed).
2. **Type Safety:** Strong static typing catches errors at compile time.
3. **Powerful Features:** Native support for pattern matching, case classes, immutability, and rich collections.
4. **Data Science Relevance:** Scala is the core language behind Apache Spark, the leading distributed data processing engine in Data Science.

---

### Q3. What is the difference between `val` and `var` in Scala?
**Answer:**
- `val` creates an **immutable** variable (cannot be reassigned after declaration, like `final` in Java).
  *Example in project:* `val id: String`, `val name: String`
- `var` creates a **mutable** variable (value can be reassigned).
  *Example in project:* `private var _isAdopted: Boolean` inside `Animal` to update adoption status.

---

### Q4. What is a Class in Scala?
**Answer:** A class is a blueprint or template for creating objects. It defines fields (attributes) and methods (behavior). In Scala, class parameters defined in the class header automatically become fields and form the primary constructor.

---

### Q5. What is an Object (Singleton Object) in Scala?
**Answer:** In Scala, the `object` keyword defines a **Singleton Object**—a class with exactly one instance created lazily when first accessed. Scala does not have a `static` keyword; instead, static-like methods, entrypoints (`def main`), and companion utilities are placed inside singleton objects (e.g., `object Main`).

---

### Q6. What is Inheritance?
**Answer:** Inheritance is an OOP concept where a child (derived) class inherits attributes and methods from a parent (base) class using the `extends` keyword. This promotes code reuse and hierarchical organization.
*Example in project:* `class Dog extends Animal(...)`, `class Cat extends Animal(...)`, `class Bird extends Animal(...)`.

---

### Q7. What is an Abstract Class?
**Answer:** An abstract class is a base class declared with the `abstract` keyword that cannot be directly instantiated using `new`. It can contain both implemented (concrete) methods and unimplemented (abstract) methods.
*Example in project:* `Animal` is abstract because an animal in the shelter must be a specific species (Dog, Cat, or Bird), not a generic animal.

---

### Q8. What is Polymorphism?
**Answer:** Polymorphism ("many forms") allows objects of different child classes to be treated as instances of their common parent class. At runtime, the JVM calls the child's specific version of the method.
*Example in project:* `val list: List[Animal]` stores Dogs, Cats, and Birds together. Calling `_.displayInfo()` automatically calls the correct subclass version.

---

### Q9. What is Method Overriding in Scala?
**Answer:** Method overriding occurs when a subclass provides its own specific implementation of a method defined in its superclass. In Scala, overriding a method requires the explicit `override` keyword, preventing accidental overrides.
*Example in project:* `override def displayInfo(): Unit` and `override def getAnimalType: String`.

---

### Q10. What is a Case Class in Scala?
**Answer:** A case class is a special kind of class optimized for holding immutable data. When defined with `case class`:
1. All constructor parameters are public and immutable (`val`) by default.
2. Standard methods (`equals`, `hashCode`, `toString`, `copy`) are automatically generated by the compiler.
3. An `apply` factory method is generated, so it can be instantiated without `new`.
4. It natively supports pattern matching.

---

### Q11. Why is `AdoptionRecord` modeled as a case class?
**Answer:** An adoption record represents historical, immutable transaction data (adoption ID, animal name, adopter, date, staff). It does not need to change once created. A case class gives us automatic equality comparison, clean string printing, and immutability without boilerplate code.

---

### Q12. What is a Collection in Scala?
**Answer:** A collection is a container data structure that holds multiple elements. Scala has two main collection hierarchies:
- **Immutable collections** (`scala.collection.immutable.*`), which cannot be modified after creation (e.g., `List`).
- **Mutable collections** (`scala.collection.mutable.*`), which allow in-place modification (e.g., `ListBuffer`).

---

### Q13. What is Pattern Matching in Scala?
**Answer:** Pattern matching is a powerful mechanism for checking a value against patterns using the `match` expression. It is like an advanced `switch` statement that can match literals, types, case classes, and tuples.
*Example in project:* Used in `Main.scala` to evaluate the user's menu choice (`1` to `11`) and in `searchChoice` (`1` vs `2`).

---

### Q14. What is Exception Handling?
**Answer:** Exception handling is a mechanism to handle runtime errors gracefully so that the program does not terminate abnormally. Scala uses `try-catch-finally` blocks:
```scala
try {
  // risky code
} catch {
  case ex: AnimalNotFoundException => println(ex.getMessage)
}
```

---

### Q15. What is a Custom Exception and why did we create them?
**Answer:** A custom exception is a user-defined class that extends `Exception`. We created them to represent domain-specific business rule violations clearly:
1. `AnimalNotFoundException`
2. `AnimalAlreadyAdoptedException`
3. `InvalidAdoptionRequestException`
4. `StaffNotFoundException`
5. `DuplicateIdException`
This makes debugging straightforward and separates domain error logic from general bugs.

---

### Q16. What is the difference between `List` and `Array` in Scala?
**Answer:**
- `List`: An immutable linked-list data structure. Fast prepend `O(1)`, but sequential access. Its size cannot change.
- `Array`: A mutable, fixed-size indexed sequence backed directly by Java's native array. Offers constant-time `O(1)` random access by index.

---

### Q17. What does the higher-order method `filter` do?
**Answer:** `filter` takes a predicate function `(A => Boolean)` and returns a new collection containing only the elements that satisfy the condition.
*Example in project:* `animals.filter(_.isAvailable)` returns all animals that have not yet been adopted.

---

### Q18. What does the higher-order method `foreach` do?
**Answer:** `foreach` takes an effectful function `(A => Unit)` and applies it to every element of the collection in sequence. It does not return a new collection.
*Example in project:* `list.foreach(_.displayInfo())` prints each animal's details to the console.

---

### Q19. What is String Interpolation in Scala?
**Answer:** String interpolation allows embedding variables and expressions directly inside string literals prefixed with `s`, `f`, or `raw`.
- `s"Hello, $name"` evaluates `$name`.
- `f"| $id%-6s | $age%2d yrs |"` allows printf-style format specifiers for aligned tabular output.

---

### Q20. Why is `Animal` an abstract class instead of a trait?
**Answer:** An abstract class is preferred when:
1. We need constructor parameters (in Scala 2.13, traits could not take constructor parameters as cleanly as classes).
2. `Animal` represents the fundamental core identity ("is-a" relationship) of every animal, rather than a mixin behavior.

---

### Q21. How does the adoption process work internally in `Shelter`?
**Answer:**
1. Looks up the animal by ID (`findAnimalById`). Throws `AnimalNotFoundException` if missing.
2. Checks if `animal.isAdopted`. Throws `AnimalAlreadyAdoptedException` if true.
3. Validates adopter name and phone number. Throws `InvalidAdoptionRequestException` if invalid.
4. Looks up staff coordinator by ID. Throws `StaffNotFoundException` if missing.
5. Mutates animal status via `animal.markAdopted()`.
6. Generates adoption ID (`ADOPT-100x`), captures `LocalDate.now()`, constructs `AdoptionRecord`, and appends to records.

---

### Q22. How does the system prevent duplicate adoptions?
**Answer:** The `Animal` base class has an internal boolean field `_isAdopted` initially set to `false`. When an animal is adopted, `markAdopted()` sets it to `true`. Any subsequent adoption call checks `if (animal.isAdopted)` and immediately raises `AnimalAlreadyAdoptedException` before altering any records.

---

### Q23. What is Encapsulation and how is it implemented?
**Answer:** Encapsulation is hiding internal object state and requiring all interaction to occur through public methods.
*In project:* In `Animal`, `_isAdopted` is `private var`. Outside code cannot modify it directly; they must query `isAdopted` / `isAvailable` and invoke `markAdopted()`. In `Shelter`, internal `ListBuffer` collections are `private` and only exposed via immutable `toList` views.

---

### Q24. What is the role of the `Shelter` class?
**Answer:** The `Shelter` class acts as the **Service / Business Logic Controller**. It manages the collections of animals, staff members, and adoption records, validates business constraints, throws domain exceptions, and calculates summary statistics. It decouples the business rules from the user interface in `Main.scala`.

---

### Q25. What is the difference between a normal Class and a Case Class?
**Answer:**
| Feature | Normal Class | Case Class |
|---|---|---|
| Instantiation | Requires `new` (unless custom `apply` written) | No `new` needed (`apply` auto-generated) |
| Field Mutability | Default is private unless specified `val`/`var` | Parameters are `val` (immutable) by default |
| `equals` / `hashCode` | Compares memory reference by default | Compares field values automatically |
| Pattern Matching | Requires explicit extractor (`unapply`) | Extractor generated automatically |
| Primary Purpose | State and behavioral modeling | Immutable data holding and transfer |

---

### Q26. What is a Companion Object in Scala?
**Answer:** A companion object is an `object` defined in the same source file and with the exact same name as a `class`. It can access the class's private members and is typically used for factory methods (`apply`), constants, and utility helpers.
*Example in project:* `object Staff` provides factory `apply(...)` methods for `class Staff`.

---

### Q27. What is Scala's `Option` type (`Some` and `None`)?
**Answer:** `Option[T]` is a container type representing an optional value: either `Some(value)` if a value is present, or `None` if it is absent. It eliminates `NullPointerException` (the billion-dollar mistake).
*Example in project:* `Staff.contactInfo` is `Option[String]`. `Shelter.findAnimalById` returns `Option[Animal]`.

---

### Q28. What is SBT and what does it do?
**Answer:** SBT (Simple Build Tool) is the standard build tool for Scala projects. It compiles Scala code, downloads and manages project dependencies, executes test suites (`sbt test`), packages the application into JAR files, and runs the application (`sbt run`).

---

### Q29. What is a Higher-Order Function?
**Answer:** A higher-order function is a function that either takes one or more functions as arguments, or returns a function as its result.
*Example in project:* `filter`, `map`, `find`, `count`, and `foreach` in `Shelter.scala` are all higher-order collection methods.

---

### Q30. If you were asked to add a new animal type (e.g., Reptile/Snake), what changes would be needed?
**Answer:**
1. Create a new class `Reptile(id, name, age, val species: String, val isVenomous: Boolean)` extending `Animal`.
2. Override `getAnimalType = "Reptile"` and `displayInfo()`.
3. Add a case `case "4" => ...` in `Main.scala` under `addNewAnimal()`.
4. Update `ShelterStatistics` to include a `reptileCount` field.
Thanks to OOP inheritance and polymorphism, the rest of the application (adoption, searches, display) works without modifying existing animal logic.
